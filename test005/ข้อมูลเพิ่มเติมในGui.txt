setDefaultCloseOperation(JFrame.DISPOSE_ON_CLOSE); ทำหน้าที่กำหนดว่า เมื่อผู้ใช้กดปุ่มปิดหน้าต่าง (ปุ่ม X) ให้ทำการ ทําลาย/คืนทรัพยากร (Dispose) 
ของหน้าต่างนั้นทิ้ง โดยที่ โปรแกรมหลัก (JVM) จะยังไม่จบการทำงาน หากยังมีหน้าต่างอื่นเปิดไว้อยู่

ค่า Parameter,ผลลัพธ์เมื่อกดปิดหน้าต่าง (ปุ่ม X)
DISPOSE_ON_CLOSE,ทำลายหน้าต่างนั้นทิ้ง คืนหน่วยความจำ แต่โปรแกรมจะยังทำงานต่อจนกว่าหน้าต่างสุดท้ายจะถูกปิด
EXIT_ON_CLOSE,สั่งปิดโปรแกรมทันที (System.exit(0)) หยุดการทำงานของทั้งแอปไม่ว่าจะเปิดไว้กี่หน้าต่างก็ตาม
HIDE_ON_CLOSE (Default),แค่ซ่อนหน้าต่างไว้ (setVisible(false)) ไม่ได้ลบออกจากหน่วยความจำ
DO_NOTHING_ON_CLOSE,"ไม่ทำอะไรเลย มักใช้เมื่อต้องการดักจับ Event เอง (เช่น เด้ง Pop-up ถามว่า ""คุณต้องการบันทึกก่อนปิดหรือไม่?"")"

คำถามแต่ละข้อเกี่ยวกับการทำงานของ Java Swing มีรายละเอียดดังนี้ครับ

### 1. "ตั้งค่า Look and Feel ให้เข้ากับระบบปฏิบัติการ (System Look and Feel) คืออะไร"

**Look and Feel (L&F)** คือรูปแบบหน้าตา รูปร่าง ปุ่ม ขอบหน้าต่าง และธีมของคอมโพเนนต์ GUI

* **คำตอบ:** โดยปกติ Java Swing จะใช้หน้าตามาตรฐานที่เรียกว่า **Metal** ซึ่งดูเป็นปุ่มสีเทาๆ ยุคเก่า ไม่ค่อยสวยงาม การตั้งค่าให้เป็น 
**System Look and Feel** จะสั่งให้ Java ไปดึงสไตล์ของ OS ที่โปรแกรมกำลังรันอยู่มาใช้ (เช่น บน Windows ปุ่มจะเป็นทรงโมเดิร์นแบบ Windows, 
บน macOS จะใช้ปุ่มฉ่ำเงาแบบ Mac) ทำให้โปรแกรมดูเนียนเหมือนแอปพลิเคชันเนทีฟของเครื่องนั้นๆ

---

### 2. `UIManager.setLookAndFeel(UIManager.getSystemLookAndFeelClassName());` ทำอะไร

คำสั่งนี้ทำงานเป็น 2 ขั้นตอนหลัก:

1. `UIManager.getSystemLookAndFeelClassName()`
* คืนค่า **ชื่อคลาส (String)** ของ Look and Feel ที่ตรงกับ OS ปัจจุบัน เช่น บน Windows จะได้ 
`"com.sun.java.swing.plaf.windows.WindowsLookAndFeel"`


2. `UIManager.setLookAndFeel(...)`
* เอาชื่อคลาสที่ได้ไปติดตั้งเป็นธีมหลักของ UI ทั้งหมดในโปรแกรม



> **คำแนะนำ:** คำสั่งนี้ควรวางไว้ที่บรรทัดแรกสุดก่อนการสร้าง Component ใดๆ เพื่อให้ปุ่มและหน้าต่างทั้งหมดถูกวาดด้วยธีมใหม่ตั้งแต่ต้น

---

### 3. `Exception ignored` มีความหมายอะไรพิเศษ ทำไมใช้ชื่อนี้

```java
try {
    UIManager.setLookAndFeel(UIManager.getSystemLookAndFeelClassName());
} catch (Exception ignored) {}

```

* **ความหมาย:** `ignored` เป็นเพียง **ชื่อตัวแปร** ของ Exception (เหมือนที่เราชอบตั้งชื่อว่า `e` หรือ `ex`)

* **ทำไมถึงตั้งว่า `ignored`:** เป็นธรรมเนียมการเขียนโค้ด (Coding Convention) เพื่อสื่อสารกับโปรแกรมเมอร์คนอื่นชัดเจนว่า 
**"ถ้าเกิดข้อผิดพลาดตรงนี้ เราตั้งใจจะข้ามมันไป ไม่ต้องจัดการอะไร (Ignore)"**

* **ผลลัพธ์:** หากเครื่องผู้ใช้ไม่รองรับธีมของ OS ด้วยเหตุผลบางอย่าง ตัว `catch (Exception ignored)` จะทำงานเงียบๆ ไม่เด้ง Crash 
แล้วปล่อยให้โปรแกรมถอยไปใช้ธีมพื้นฐาน (Metal) แทน

---

### 4. "เรียกใช้งาน GUI บน Event Dispatch Thread (EDT) คืออะไร ทำไมดูสำคัญ"

---

* **Event Dispatch Thread (EDT)** คือ **Thread พิเศษเพียงหนึ่งเดียว** ใน Java Swing ที่มีหน้าที่ทำ 2 อย่างหลัก:
1. **วาดและอัปเดตหน้าจอ (Rendering/Repainting)**
2. **จัดการกับ Event จากผู้ใช้** (เช่น การคลิกเมาส์ การพิมพ์คีย์บอร์ด)



#### ทำไมถึงสำคัญมาก?

Java Swing **ไม่ใช่ Thread-Safe** นั่นแปลว่า หากมี Thread หลายตัวมาแย่งกันแก้ไขหน้าต่างวาดภาพพร้อมกัน อาจเกิดปัญหาข้อมูลขัดแย้ง (Race Condition) 
หน้าจอกระตุก หรือค้างได้ กฎเหล็กของ Swing จึงมีอยู่ว่า **"ทุกอย่างที่เกี่ยวกับการสร้าง อัปเดต หรือปรับเปลี่ยน GUI ต้องทำบน EDT เท่านั้น"**

---

### 5. `SwingUtilities.invokeLater(() -> { ... });` คืออะไร ทำอะไร

`SwingUtilities.invokeLater` คือคำสั่งสำหรับ **ต่อคิวงาน (Enqueue)** ส่งก้อนโค้ดที่เราเขียนไปให้ **EDT** เป็นผู้ประมวลผล

* **ทำไมต้องใช้ `invokeLater` ใน `main`?**
เมธอด `main()` ของ Java จะรันอยู่บน **Main Thread** ไม่ใช่ EDT หากเราสั่งสร้าง `new Gui()` บน `main()` ตรงๆ 
จะเป็นการละเมิดกฎ Thread-Safety ของ Swing
* การใส่ `SwingUtilities.invokeLater` เป็นการส่งคำสั่งไปบอก EDT ว่า *"ถ้าจัดการงานคิวอื่นเสร็จแล้ว ช่วยมาสร้างและแสดงหน้าต่าง Gui() ให้หน่อยนะ"*

---

### 6. `Gui frame = new Gui(); frame.setVisible(true);` ทำไมตัวนี้ต้องอยู่ตรงนี้

```java
SwingUtilities.invokeLater(() -> {
    Gui frame = new Gui();
    frame.setVisible(true);
});

```

* **ทำไมต้องสร้าง (`new Gui()`) ตรงนี้:** เพื่อให้การอินสแตนชิเอตคลาส GUI และคอมโพเนนต์ภายในทั้งหมด (เช่น ปุ่ม, Canvas, Layer)
 ถูกสร้างขึ้นอย่างปลอดภัยบน EDT
* **ทำไมต้อง `frame.setVisible(true)` ตรงนี้:** หน้าต่าง `JFrame` โดยค่าเริ่มต้นจะมีสถานะซ่อนอยู่ (`visible = false`) 
คำสั่งนี้จะเปลี่ยนเป็น `true` เพื่อสั่งให้ EDT **เริ่มต้นวาดหน้าต่างขึ้นมาบนจอภาพ** ต่อหน้าผู้ใช้ทันที
